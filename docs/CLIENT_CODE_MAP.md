# Как устроен код Alt

Этот документ дополняет [инструкцию по локальной разработке](LOCAL_DEVELOPMENT.md).
Начните с `public/index.html`, если меняете внешний вид, и с `public/js/app.js`,
если меняете действие кнопки. Рабочий сайт обновляется **только** после объединения
изменений в `main` и успешных проверок; локальные правки его не меняют.

## Карта файлов

| Файл                         | За что отвечает                                                             | Чего здесь нет                     |
| ---------------------------- | --------------------------------------------------------------------------- | ---------------------------------- |
| `public/index.html`          | Экраны входа, регистрации, комнат и сообщений; шаблон Vue                   | Запросов к Synapse                 |
| `public/css/style.css`       | Все стили рабочего клиента; карта разделов — в начале файла                 | Логики кнопок                      |
| `public/js/app.js`           | Поля форм, нажатия кнопок, видимые ошибки                                   | Низкоуровневых запросов Matrix     |
| `public/js/matrix-client.js` | Клиент Matrix SDK, синхронизация, сессия, комнаты и сообщения               | Разметки страниц                   |
| `public/js/matrix-core.js`   | Адрес Synapse, вспомогательные функции сессии/регистрации/комнат            | Состояния Vue                      |
| `build-client.js`            | Собирает шаблон Vue и браузерный код в `public/js/alt.js`                   | Запуска сайта                      |
| `server.js`                  | Раздаёт `public/`, подключает API приглашений и задаёт ограничения браузера | Базы пользователей                 |
| `ops/alt-auto-update.js`     | На VM устанавливает проверенный коммит `main`                               | Кода, исполняемого браузером       |
| `tests/`                     | Проверки с подставными ответами SDK и браузера                              | Настоящего входа в рабочий Synapse |

`public/js/alt.js` — результат сборки, его **не редактируют** и не добавляют
в Git. `docs/LOCAL_DEVELOPMENT.md` описывает команды для повседневной работы.

Управление регистрационными приглашениями — отдельное исключение: браузер
вызывает защищённый API Express. Его устройство и настройка описаны в
[`INVITATIONS.md`](INVITATIONS.md). `lib/invitations.js` работает только на сервере,
`public/js/invitations.js` управляет окном, а `invitationRequest()` в
`matrix-client.js` передаёт пользовательскую сессию серверу Alt.

## Путь данных от кнопки до экрана

```text
Нажатие в public/index.html
    ↓ событие Vue
Обработчик в public/js/app.js
    ↓ вызов mc.*
Функция в public/js/matrix-client.js
    ↓ SDK или вспомогательная функция в matrix-core.js
Synapse: https://synapse.creatusest.ru
    ↓ события синхронизации и комнат
matrix-client.js: refreshRooms() → notify()
    ↓ подписка subscribe()
app.js: s.value → Vue обновляет public/index.html
```

Поля входа, регистрации и отправки хранятся в `app.js`. Состояние соединения,
комнаты и открытая переписка хранятся в `matrix-client.js`. Для изменения
отступов не нужно менять JavaScript; для новой кнопки потребуется связать
разметку с обработчиком в `app.js` и, возможно, с методом клиента Matrix.

## Экран и кнопки: `public/js/app.js`

`setup()` создаёт данные, доступные шаблону. `s` — текущий снимок клиента;
`active`, `joined` и `invited` вычисляются из комнат. `subscribe()` присылает
новые снимки, а `onUnmounted()` снимает подписку. Ссылка с параметром
`registration_token` или `token` заполняет поле кода регистрации и удаляется
из адресной строки, чтобы не оставлять код в истории страницы.

| Функция                      | Когда вызывается               | Что меняет                                                                                             |
| ---------------------------- | ------------------------------ | ------------------------------------------------------------------------------------------------------ |
| `doAuth(kind)`               | Отправка любой из двух форм    | Выбирает поля, вызывает `mc.login()` или `mc.register()`, показывает ошибку, временно блокирует повтор |
| `doLogin()` / `doRegister()` | Кнопки входа и регистрации     | Передают соответствующий вид действия в `doAuth()`                                                     |
| `logout()`                   | Кнопка «Выйти»                 | Вызывает выход клиента и очищает видимые поля                                                          |
| `select(r)`                  | Выбор комнаты слева            | Меняет открытую комнату без запроса к серверу                                                          |
| `join(r)`                    | Принятие приглашения в комнату | Вызывает `mc.joinRoom()`                                                                               |
| `loadOlder()`                | Кнопка «История»               | Просит предыдущие события открытой комнаты                                                             |
| `send()`                     | Отправка сообщения             | Не отправляет пустой текст; очищает поле после успеха                                                  |
| `doCreateRoom()`             | Создание комнаты               | Передаёт название и видимость в Matrix; закрывает форму после успеха                                   |
| `doInvite()`                 | Кнопка «Пригласить»            | Приглашает Matrix ID в открытую комнату                                                                |
| `fmt(ts)`                    | Показ времени сообщения        | Преобразует метку времени по настройкам браузера                                                       |

При загрузке `onMounted()` вызывает `mc.restoreSession()`. Наблюдатель
за количеством сообщений прокручивает переписку после обновления разметки.

## Подключение и комнаты: `public/js/matrix-client.js`

`state` хранит данные экрана. `phase` определяет форму входа, ожидание или
переписку; `connection` отдельно отражает состояние сети. `snapshot()`
возвращает снимок состояния, `subscribe()` подписывает Vue, а `notify()`
передаёт новый снимок после изменений. `refreshRooms()` преобразует комнаты
SDK через `buildRoomViews()`.

`wire()` подписывает SDK на синхронизацию и события комнат: при готовности
показывает переписку и пользователя, при появлении сообщения перечитывает
комнаты и уведомляет интерфейс. `reset()` очищает данные экрана перед новым
входом либо после выхода.

| Функция            | Назначение                                                                                 |
| ------------------ | ------------------------------------------------------------------------------------------ |
| `login()`          | Входит по паролю, сохраняет выданную сессию и начинает синхронизацию                       |
| `register()`       | Проводит регистрацию с кодом, сохраняет новую сессию и начинает синхронизацию              |
| `restoreSession()` | Проверяет сохранённый ключ: удаляет его при отказе сервера, но сохраняет при проблеме сети |
| `logout()`         | Пытается завершить серверную сессию и остановить SDK; затем очищает локальную сессию       |
| `selectRoom()`     | Устанавливает ID открытой комнаты локально                                                 |
| `joinRoom()`       | Принимает приглашение через SDK                                                            |
| `loadOlder()`      | Просит до 30 прежних событий комнаты и обновляет отображение                               |
| `sendText()`       | Отправляет текст через SDK                                                                 |
| `createRoom()`     | Создаёт публичную или закрытую комнату и возвращает её ID                                  |
| `inviteUser()`     | Приглашает пользователя в комнату по Matrix ID                                             |

## Вспомогательные правила: `public/js/matrix-core.js`

- `HOMESERVER` — адрес рабочего Synapse. Не меняйте его ради тестов: локально
  запущенный Alt всё равно обращается к **настоящему серверу**.
- `makeSessionStore()` создаёт `save/load/clear` для `localStorage`. Хранится
  ключ доступа и ID, **не пароль**. `validateSession()` проверяет ключ через
  `whoami` и различает отказ сервера и временную недоступность сети.
- `performLogin()` сохраняет данные из ответа SDK; `isReadySyncState()`
  определяет, когда уже можно показать загруженные комнаты.
- `registerWithUIA()` последовательно отправляет код регистрации и другие
  требуемые сервером шаги. Список `completed` показывает принятые шаги;
  ответ `401` может быть обычным продолжением регистрации. Новый аккаунт
  считается созданным **только после успешного ответа** Synapse.
- `buildRoomViews()` превращает события SDK в сообщения для шаблона. Клиент
  пока не умеет сквозное шифрование: зашифрованные события видны как заглушки,
  а отправка в такую комнату скрыта в `public/index.html`.

## Сборка, сервер и обновление сайта

`npm run build` запускает `build-client.js`: извлекает шаблон из
`public/index.html`, собирает `app.js` и зависимости в `public/js/alt.js`.
`server.js` отдаёт файлы `public/` и ограничивает разрешённые браузеру
скрипты, шрифты и сетевые соединения. Synapse принимает запросы **напрямую
из браузера**, а не через этот сервер, кроме административного управления
регистрационными приглашениями, описанного выше.

На VM `ops/alt-auto-update.js` проверяет, что в `/opt/alt` нет правок, забирает
коммит `main`, убеждается в успешной проверке **именно этого SHA** на GitHub,
повторяет `npm run check` на VM, перезапускает Alt и проверяет ответ сайта.
Файл `deployed-sha` записывается в конце. Ошибка не даёт отметить установку
успешной; **автоматического отката нет**. При изменении службы помните, что
копии файлов из `ops/` установлены на VM отдельно.

## Как проверять изменения

1. Перед отправкой запустите `npm run check`: форматирование, проверка кода,
   сборка и тесты.
2. Откройте локальную страницу и проверьте свой сценарий в браузере.
3. Тесты `tests/matrix-core.test.js` используют подставные ответы регистрации
   и сессии; `tests/client-smoke.test.js` проверяет запуск собранного экрана.
4. Автоматические тесты **не подтверждают реальный вход, создание пользователя
   или переписку** на рабочем Synapse. Для таких проверок используйте только
   согласованную тестовую учётную запись и незашифрованную комнату; не меняйте
   чужие данные.
