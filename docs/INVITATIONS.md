# Приглашения для регистрации в Alt

Alt использует **Registration Tokens API Synapse**, без собственной базы
токенов и фонового задания истечения срока. Ссылка передаёт код в уже
существующую форму регистрации Matrix UIA:

```text
https://alt.creatusest.ru/?registration_token=TOKEN
```

## Как пользоваться

1. Войдите в Alt и нажмите «Пригласить пользователя» слева.
2. Выберите срок (1 час, 24 часа, 7 дней) и число регистраций (1 или 5).
   По умолчанию выбраны 24 часа и одна регистрация.
3. Нажмите «Создать приглашение», затем «Копировать» и передайте ссылку
   приглашённому человеку. Код не отправляется автоматически другим участникам.
4. Переключайте список между активными и недействительными. «Обновить список»
   перечитывает данные непосредственно из Synapse, включая старые токены.
5. «Отозвать» устанавливает лимит в ноль. Запись остаётся в недействительных.

Список общий для всех разрешённых пользователей: они могут просматривать
и отзывать любые регистрационные токены этого Synapse, включая созданные
другими административными инструментами. Учёта владельцев в этой реализации нет.

### Статусы

- **Активно:** срок не закончился и есть свободные места.
- **Истекло:** достигнут `expiry_time` (время Unix в миллисекундах).
- **Лимит использован:** `completed + pending >= uses_allowed`.
- **Недействительно:** `uses_allowed = 0`, в том числе после отзыва.

Существующие токены могут иметь `null` в сроке или лимите: это «Без срока»
и «Без лимита». Новые токены Alt всегда ограничены обоими параметрами.
`pending` — регистрации, которые уже подтвердили код, но ещё не завершились.
Они занимают места; после освобождения таких мест приглашение может вновь
стать действующим. Истечение проверяет сам Synapse, а окно лишь отображает
текущее время и счётчики. Перед копированием Alt повторно получает токен.
Отзыв запрещает новые использования, но уже подтверждённые сервером шаги
регистрации могут завершиться. Отзыв не удаляет созданных пользователей.

## Требования к Synapse

- Включены регистрация и `registration_requires_token`.
- Доступен штатный `/_synapse/admin/v1/registration_tokens`.
- Есть действующий Matrix access token администратора Synapse, используемый
  только сервером Alt. Желательно выделить для этого отдельную служебную
  административную учётную запись.
- Эти методы не поддерживаются при передаче регистрации в Matrix
  Authentication Service (MAS). Здесь реализован только Synapse Admin API.

Никакие настройки Synapse не меняются при установке Alt. Административный API
нужен **серверу Alt**, а не браузеру. Если Caddy публикует только `/_matrix/`
и `/_synapse/client/`, используйте доступный VM внутренний адрес Synapse.
Не публикуйте Admin API в интернете ради этой функции.

## Переменные окружения Express

| Переменная                     | Значение                                                                                                                                                                                     |
| ------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `ALT_INVITES_SYNAPSE_URL`      | Корень доверенного Synapse, без пути, параметров и пароля. По умолчанию `https://synapse.creatusest.ru`. Через него выполняются и `whoami`, и административные запросы.                      |
| `ALT_INVITES_ALLOWED_USERS`    | Полные Matrix ID через запятую, например `@alice:synapse.creatusest.ru,@bob:synapse.creatusest.ru`. Совпадение точное, с учётом регистра. Пустой список запрещает управление всем.           |
| `ALT_INVITES_ADMIN_TOKEN_FILE` | Абсолютный путь к файлу с административным access token, например `/etc/alt/invites-admin-token`. Файл должен быть читаем пользователем службы Alt и находиться вне репозитория и `public/`. |

URL должен указывать на тот же сервер пользователей, что и `HOMESERVER` в
`public/js/matrix-core.js`. HTTP допустим для доверенной изолированной сети;
для сетей, которым не доверяете, используйте HTTPS, поскольку ключи передаются
в заголовках. Не помещайте ключи в URL.

Сервер читает эти настройки и секрет при запуске. Для применения изменений
нужен перезапуск `alt-client`, не Synapse. Если файл не читается или настройки
неполные, приглашения вернут `503`, но обычный клиент продолжит работать.

### Настройка на VM вручную

1. Создайте `/etc/alt` с доступом только администратора и группы службы Alt.
   Сохраните административный access token в `/etc/alt/invites-admin-token`.
   Рекомендуемые владелец и права: `root:alt`, каталог `0750`, файл `0640`.
   Не вставляйте секрет в команды, историю терминала, Git, браузер или журнал.
2. Создайте `/etc/alt/invites.env` (например, `root:root`, права `0600`):

    ```ini
    ALT_INVITES_SYNAPSE_URL=http://10.10.10.9:8008
    ALT_INVITES_ALLOWED_USERS=@alice:synapse.creatusest.ru
    ALT_INVITES_ADMIN_TOKEN_FILE=/etc/alt/invites-admin-token
    ```

    Замените пользователя на реально разрешённый ID. Не используйте пример
    как автоматическое разрешение доступа.

3. Через `systemctl edit alt-client` добавьте:

    ```ini
    [Service]
    EnvironmentFile=/etc/alt/invites.env
    ```

4. После установки проверенного кода выполните `systemctl daemon-reload`
   и `systemctl restart alt-client`. Секрет читается процессом `alt-client`,
   а не пользователем `alt-deploy`.
5. Проверьте окно разрешённым пользователем, затем убедитесь, что другой
   пользователь получает понятный отказ. Не запускайте регистрацию чужих
   пользователей ради проверки.

Файл `.env.example` содержит только имена настроек. Express не читает `.env`
автоматически: при локальном запуске передайте окружение процессу Node.
Не делайте отдельную копию административного секрета для браузерной сборки.

## Защищённый API Alt

Каждый запрос требует `Authorization: Bearer <пользовательский access token>`.
Express проверяет его через `GET /_matrix/client/v3/account/whoami`, затем
сравнивает подтверждённый ID со списком разрешённых. ID из тела запроса не
используется. Административный ключ применяется только к запросам Admin API.
Ответы помечены `Cache-Control: no-store`; подробности ошибок Synapse и
секреты не возвращаются и не записываются кодом API в журнал.

| Метод Alt                                              | Действие Synapse                                                                                |
| ------------------------------------------------------ | ----------------------------------------------------------------------------------------------- |
| `GET /api/invitations`                                 | `GET /_synapse/admin/v1/registration_tokens`                                                    |
| `GET /api/invitations/{token}`                         | `GET /_synapse/admin/v1/registration_tokens/{token}`                                            |
| `POST /api/invitations` с `{ "hours": 24, "uses": 1 }` | `POST /_synapse/admin/v1/registration_tokens/new`; Synapse сам генерирует код длиной 32 символа |
| `POST /api/invitations/{token}/revoke`                 | `PUT /_synapse/admin/v1/registration_tokens/{token}` с `{ "uses_allowed": 0 }`                  |

Официальный `DELETE /_synapse/admin/v1/registration_tokens/{token}` существует,
но Alt его не вызывает и не предоставляет удаление: отзыв через `PUT`
сохраняет историю. Произвольное изменение срока и лимита также не предоставляется.
Коды ответов Alt: `400` — параметры, `401` — отсутствующая/недействительная
сессия, `403` — нет разрешения, `404` — нет токена/метода, `429` — частота,
`502/503` — ошибка данных, настройки или доступности Synapse.

Создание ограничено пятью попытками в час **на Matrix ID**, независимо от
IP и числа сессий. Неудачные обращения после проверки параметров тоже
считаются попытками, чтобы не перегружать Synapse. Счётчики находятся в памяти
одного процесса и сбрасываются при его перезапуске. Для нескольких экземпляров
Alt потребуется общее ограничение частоты вне приложения. Сам Synapse
остаётся единственным хранилищем кодов, сроков и числа использований.

## Файлы и проверки

- `lib/invitations.js` — конфигурация, проверка личности, права, частота, Synapse API.
- `public/js/invitations.js` — состояние окна, фильтр, копирование и отзыв.
- `public/js/matrix-client.js` — запрос к Alt с пользовательской сессией.
- `public/index.html`, `public/css/style.css` — окно и его оформление.
- `tests/invitations-api.test.js`, `tests/invitations-ui.test.js` — имитации
  ответов Synapse, проверки прав, лимитов, сроков, отзыва и окна.

Запуск: `npm run check`. Автоматические тесты не создают реальных токенов
на рабочем сервере. Протестировать настоящую административную интеграцию
можно только после ручной настройки сервера. Список не обновляется постоянно
в фоне: нажимайте «Обновить список», чтобы увидеть регистрации из других клиентов.
