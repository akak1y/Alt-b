Alt-b: локальная разработка для смешариков 🛠️
Задача: изменить интерфейс или код Alt-b, проверить результат у себя в браузере и отправить изменения на ревью, не загружая файлы на VPS.

Эта инструкция рассчитана на тех, кто впервые работает с проектом. Команды сверены с текущими скриптами package.json.

Быстрые ссылки: исходники Alt-b · основной сайт · Pull Requests · Issues · GitHub Actions
1. Как это работает
Ваш компьютер                         VPS
┌──────────────────────────┐         ┌─────────────────────────────┐
│ Alt-b на localhost:3000  │ ─HTTPS→ │ Matrix Synapse              │
│ HTML + CSS + Vue         │         │ synapse.creatusest.ru       │
└──────────────────────────┘         └─────────────────────────────┘

Редактирование локальных файлов НЕ обновляет сайт alt.creatusest.ru.
Но сообщения, комнаты и аккаунты на Synapse — настоящие!
Важно: локальный клиент подключается к рабочему Matrix Synapse. Для проверки кнопок можно использовать обычный аккаунт, а для действий с комнатами и регистрацией лучше создать отдельную тестовую учётную запись и комнату. Не удаляйте чужие данные ради эксперимента.

Откройте PowerShell (Windows) или терминал (Linux) и проверьте установку:
git --version
node --version
npm --version
Должны отобразиться версии программ. Если git или node не найден, перезапустите терминал после установки.
3. Первый запуск
В терминале перейдите в удобную папку и выполните:
git clone https://github.com/akak1y/Alt-b.git
cd Alt-b
npm ci
npm ci установит зависимости из package-lock.json. В отличие от npm install, эта команда рассчитана на воспроизводимую установку и не должна менять lock-файл.
Linux
npm run dev
Windows (PowerShell)
npm run dev:win
Откройте http://localhost:3000/.

Если терминал занят работающим сервером, это нормально: оставьте его открытым. Для дополнительных команд откройте второй терминал в папке Alt-b.

Остановить приложение: Ctrl + C в терминале с сервером.
Ничего отправлять на GitHub или VPS для локального запуска не нужно. Порт по умолчанию — 3000. Если порт занят, сначала остановите другое приложение, использующее его.

4. Как менять файлы и смотреть результат
Файл	Что менять
public/index.html	Разметка форм, кнопок и экранов
public/css/style.css	Цвета, отступы, шрифты, адаптивность
public/js/app.js	Действия интерфейса на Vue
public/js/matrix-client.js	Связь клиента с Matrix SDK
public/js/matrix-core.js	Настройки Synapse, сессии и вспомогательная логика
tests/	Автоматические тесты


Пример: изменить внешний вид кнопки.
1. Откройте public/css/style.css в редакторе.
2. Найдите стиль нужной кнопки (например, .primary).
3. Измените CSS и сохраните файл.
4. Вернитесь в http://localhost:3000/ и обновите страницу (Ctrl + R).
5. Не понравилось? Отмените изменение в редакторе или через Git.
Важное отличие Windows и Linux
- Linux: npm run dev следит за исходниками и при изменениях пересобирает приложение/перезапускает сервер. Страницу в браузере всё равно нужно обновлять вручную: HMR здесь пока нет.
- Windows: npm run dev:win не пересобирает frontend автоматически. После правок public/index.html или public/js/*.js откройте второй терминал в папке проекта и выполните:
  npm run build
  Затем обновите страницу. CSS из public/css/style.css раздаётся напрямую, поэтому для его изменений обычно достаточно обновить страницу.
Если кажется, что браузер показывает старую версию, попробуйте Ctrl + Shift + R.
5. Как работать, чтобы не сломать основной сайт
Основная ветка main используется для развёртывания на сервере. Не отправляйте туда незавершённые эксперименты.

Перед новой задачей, когда предыдущие изменения сохранены:
git switch main
git pull --ff-only
git switch -c feature/new-login-style
Теперь изменения изолированы в отдельной ветке feature/new-login-style. Имя ветки придумайте по смыслу задачи: fix/login-error, feature/user-profile, style/chat-layout.

Проверяйте, где находитесь и какие файлы изменили:
git branch --show-current
git status
Не выполняйте git switch main поверх несохранённых изменений, если Git сообщает, что переключение затронет ваши файлы. Сначала сохраните изменения коммитом или разберитесь с git stash.
6. Проверки перед отправкой
В папке проекта выполните:
npm run check
Команда запускает проверку форматирования (Prettier), ESLint, сборку клиента и тесты Vitest.

Если проверка форматирования не прошла, можно отформатировать файлы командой:
npm run format
npm run check
Не забывайте затем посмотреть git diff: форматирование может затронуть больше строк, чем вы ожидали.

Автоматические тесты не заменяют ручную проверку в браузере и не подтверждают работу реального Synapse. Проверяйте собственный сценарий: открывается ли страница, работает ли кнопка, не появились ли ошибки в консоли браузера (F12 → Console).
7. Отправляем изменения через Pull Request
Когда всё работает:
git status
git diff
git add .
git commit -m "style: обновить оформление входа"
git push -u origin feature/new-login-style
git add . добавляет все изменения в текущей папке: перед коммитом проверяйте git status, чтобы случайно не отправить лишнее. Не добавляйте .env, пароли, ключи или токены.

Дальше:
1. Откройте репозиторий Alt-b на GitHub.
2. Нажмите Compare & pull request (обычно GitHub предложит кнопку после push) или перейдите на страницу New pull request.
3. Убедитесь: base: main, compare: ваша ветка.
4. Кратко опишите, что поменяли, зачем и как проверяли.
5. Создайте PR и дождитесь ревью. Не выполняйте merge самостоятельно без согласования с командой.
Пример описания PR:
## Что изменено
- Обновлён внешний вид формы входа.
- Исправлены отступы на узких экранах.

## Как проверено
- npm run check — успешно.
- Открыл localhost:3000 в Firefox.
- Проверил форму на узком и широком экране.

## Известные ограничения
- Нет.
Нет прав на запись в репозиторий? Создайте Fork в своём аккаунте GitHub и отправляйте ветку туда. Затем откройте PR из форка в akak1y/Alt-b:main. Прямой push в origin без прав не сработает.
8. Как обновлять свою копию
Когда хотите получить свежую основную версию и у вас нет незавершённых изменений:
git switch main
git pull --ff-only
npm ci
npm ci особенно полезна после изменений в package.json или package-lock.json.

Если вы уже работаете в отдельной ветке, не нужно слепо переключаться на main: сначала сохраните свою работу. Для включения новых изменений main в свою ветку используйте git merge main или git rebase main, понимая разницу между этими командами. При конфликтах лучше обратиться к участнику, который уверенно работает с Git.
9. Частые вопросы
«Открываю localhost, но ничего нет». Проверьте, что команда запуска ещё работает в терминале и нет ошибки о занятом порте. Нужный адрес: http://localhost:3000/, не https://.

«Изменил JS, а на странице всё по-старому». На Windows повторите npm run build и обновите страницу. На Linux убедитесь, что npm run dev не завершился с ошибкой.

«Локальная версия не входит в Matrix». Откройте инструменты разработчика (F12 → Network/Console). Локальный интерфейс обращается к https://synapse.creatusest.ru: проверьте, доступны ли запросы, нет ли ошибок CORS, CSP или сети. Не меняйте настройки рабочего Synapse без согласования.

«npm не запускается в PowerShell». Если ошибка связана с npm.ps1 и политикой выполнения скриптов, можно вызвать npm.cmd ci, npm.cmd run dev:win и аналогично другие npm-команды. Глобально ослаблять настройки безопасности PowerShell ради проекта не требуется.

«На GitHub всё зелёное, значит сайт работает?» Нет. CI проверяет сборку, стиль кода и тесты. Продакшен развёртывается отдельно после успешного запуска CI, а доступность Matrix и пользовательские сценарии нужно проверять дополнительно.
