# Alt

Тестовый веб-клиент Matrix. Браузер работает с Synapse напрямую через
`matrix-js-sdk`; Express раздаёт файлы из `public/`, выставляет Content Security
Policy (CSP) и предоставляет защищённый API управления регистрационными
приглашениями. Собственной базы пользователей или регистрационных токенов нет.

## Запуск

Нужны Node.js 20 или новее и npm. Устанавливайте **все** зависимости, включая
зависимости для сборки:

```sh
npm ci
npm start
```

Откройте `http://localhost:3000/`. Порт можно изменить переменной окружения
`PORT` (например, `PORT=4000 npm start` в Unix-подобной оболочке).
`npm start` перед запуском сервера собирает клиент через esbuild. Для разработки
используйте `npm run dev`; на Windows доступна команда `npm run dev:win`.
После изменений исходников в режиме `dev:win` запускайте `npm run build`
повторно: этот режим не пересобирает клиент при перезапуске сервера.

В `public/index.html` находится шаблон интерфейса. Сборка в `build-client.js`
заранее компилирует его средствами Vue и объединяет код с `matrix-js-sdk`
в `public/js/alt.js`. Собранный файл не хранится в Git.

Все стили работающего клиента находятся в `public/css/style.css` — его
подключает `public/index.html`. В начале файла есть карта разделов, а перед
каждым крупным блоком указано, где он используется. Поправки для узких
экранов находятся в конце этого же файла.
Для знакомства с функциями клиента и их связью с интерфейсом начните с
[`docs/CLIENT_CODE_MAP.md`](docs/CLIENT_CODE_MAP.md); команды для локальной
работы собраны в [`docs/LOCAL_DEVELOPMENT.md`](docs/LOCAL_DEVELOPMENT.md).

Из дизайнерского макета на экран входа перенесены композиция, изображения и
шрифт Share Tech Mono, но формы используют действующую авторизацию Matrix.
Шрифт хранится локально в `public/fonts/` вместе с лицензией SIL OFL; для
кириллицы, которой в нём нет, браузер использует запасной моноширинный шрифт.
В переписке используются те же цвета и шрифт. Отдельный черновик удалён:
его демонстрационный скрипт выводил пароль в консоль вместо авторизации.
Музыка в рабочий клиент не включена.

## Работа с Matrix

Адрес Synapse задан в `public/js/matrix-core.js`:
`https://synapse.creatusest.ru`. Логин, сессия, синхронизация комнат,
сообщения, приглашения и история обрабатываются в браузере. Данные сессии
хранятся в `localStorage`; CSP ограничивает источники скриптов и соединений.
Сквозное шифрование (E2EE) **не поддерживается**: для проверки переписки
используйте незашифрованную комнату. Для регистрации по приглашению можно
ввести код в форме регистрации или открыть ссылку вида
`https://alt.creatusest.ru/?registration_token=КОД`. Ссылка откроет форму
регистрации и подставит код; после открытия код удаляется из адресной строки.
Регистрация проверена на имитации ответов Synapse; создание пользователя на
рабочем сервере в автоматические тесты не входит.

`docker-compose.yml` описывает **только отдельный тестовый Synapse** с данными
в `matrix/data/`. Он не запускает Alt и не подменяет адрес Synapse,
закреплённый в клиенте; его настройка и данные не меняются при сборке Alt.
Переменная `MATRIX_SERVER_NAME` в `.env.example` относится только к этому
необязательному окружению. Сервер Alt читает `PORT` из окружения и не загружает
файл `.env` автоматически.

## Приглашения новых пользователей

Кнопка «Пригласить пользователя» открывает управление ссылками регистрации:
создание на 1 час, 24 часа или 7 дней с лимитом 1 или 5 регистраций,
копирование, просмотр активных/недействительных ссылок и отзыв. По умолчанию
выбраны 24 часа и одна регистрация. Видны также старые токены Synapse.

Доступ требует действующей Matrix-сессии и явного разрешения серверного
администратора. При отсутствии настройки клиент продолжает работать, а окно
приглашений объясняет причину отказа.

Переменные сервера: `ALT_INVITES_SYNAPSE_URL`, `ALT_INVITES_ALLOWED_USERS`,
`ALT_INVITES_ADMIN_TOKEN_FILE`. Секрет хранится в отдельном серверном файле;
`.env` автоматически не загружается. Подробная настройка, правила доступа и
ограничения описаны в [docs/INVITATIONS.md](docs/INVITATIONS.md).

## Проверки

```sh
npm run check
```

Команда запускает Prettier, ESLint, сборку и тесты. Тесты проверяют клиент
на имитациях SDK/браузера; **реальное подключение к Synapse они не проверяют**.

## Автоматическое обновление сайта

Проверка GitHub запускается только после изменений в ветке `main`:
`.github/workflows/check-main.yml` устанавливает зависимости и выполняет
`npm run check`. Запросы на объединение и другие ветки не запускают эту проверку.

На сервере Alt `10.10.10.10` каждые пять минут запускается
`alt-auto-update.timer`. Программа `ops/alt-auto-update.js` узнаёт точный
коммит `main`, сверяет его с **успешной завершённой проверкой этого коммита**
на GitHub и только после этого обновляет `/opt/alt`, повторяет проверки,
перезапускает `alt-client.service` и проверяет сайт по HTTPS. При ошибке
проверок или недоступности GitHub обновление не выполняется; попытка
повторяется при следующем запуске таймера. Входящий SSH из интернета и
программа GitHub на рабочем сервере для этого не нужны.

Файлы для службы и таймера находятся в `ops/`. На сервере установлена их
копия в `/etc/systemd/system/`, копия программы обновления — в
`/usr/local/libexec/`, а `ops/alt-deploy.sudoers` ограничивает право
пользователя `alt-deploy` одним перезапуском `alt-client.service`. При
изменении этих файлов их необходимо отдельно обновить на сервере.

Состояние можно посмотреть командами `systemctl status alt-auto-update.timer`
и `journalctl -u alt-auto-update.service`. Сбой обновления не откатывает
версию автоматически — его нужно разобрать по журналу перед ручным откатом.
